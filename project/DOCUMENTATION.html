1. Project Overview

A complete desktop application for managing airport operations including flights, passengers, pilots, co-pilots, reports, and LAN chat. Built entirely in Java with JavaFX for the graphical interface. All UI is created programmatically in Java code — no FXML files or Scene Builder used.

Key Features

  • Dashboard — Overview with stat cards, management grid, upcoming flights table, quick actions
  • Flight Management — Full CRUD with inline status change (SCHEDULED/BOARDING/DEPARTED/CANCELLED)
  • Passenger Management — Add, view, search, delete passengers
  • Pilot Roster — Salary, flight hours, license management
  • Co-Pilot Roster — Salary, hours, language management
  • Reports — 6 report types (Flight, Passenger, Pilot, Co-Pilot, Employee, Full Summary) with save-to-file functionality
  • Chat (LAN) — Real-time socket chat via Python server
  • Search — Global search bar filters the current page's table
  • Welcome Screen — Animated landing page with airplane pulse
  • Normal Employees — CRUD management for regular employees (name, identity, nationality, salary)
  • Data Persistence — Passengers saved to passengers.txt; flights log written to flights-log.txt on app close

3. Installation & How to Run

3.1 Compile

cd /home/idkrealyyea/Desktop/PROJECT/project
rm -rf bin
mkdir -p bin
javac \
  --module-path "lib/javafx.base.jar:lib/javafx.controls.jar:lib/javafx.graphics.jar:lib/javafx.fxml.jar:lib/javafx.media.jar:lib/javafx.swing.jar:lib/javafx.web.jar" \
  --add-modules javafx.controls,javafx.graphics,javafx.base,javafx.fxml \
  -d bin \
  $(find src -name "*.java" ! -name "Chatwindowcontroller.java") 2>&1

3.2 Run (via F5 in VS Code)

Use the "Airport Management" configuration in .vscode/launch.json. The F5 key launches via this config.

Important: Do NOT use the green "Run" button in VS Code — it does not pass the required JVM module arguments. Always use F5 (debug) or the launch.json config.

3.3 Run via Terminal

cd /home/idkrealyyea/Desktop/PROJECT/project
java --module-path "lib/javafx.base.jar:lib/javafx.controls.jar:lib/javafx.graphics.jar:lib/javafx.fxml.jar:lib/javafx.media.jar:lib/javafx.swing.jar:lib/javafx.web.jar" \

3.4 Run Chat Server

cd /home/idkrealyyea/Desktop/PROJECT/project/server
python3 server.py

The server listens on 0.0.0.0:5555 and supports multiple simultaneous clients.

3.5 Entry Point

Launcher.java → calls Main.main() → JavaFX launches the application.

This two-class pattern bypasses JDK 17's module system check that prevents launching from Main directly.

8. Navigation System

How it works

  1. Sidebar has 9 nav buttons: Dashboard, Flights, Passengers, Pilots, Co-Pilots, Reports, Chat, Settings, Employees
  2. Clicking a button calls mainApp.navigateTo(page)
  3. Main.navigateTo() stops any running FadeTransition, resets opacity, clears centerStack, creates the appropriate page, and adds it
  4. Each page is a VBox/StackPane added to the center of the BorderPane
  5. FadeTransition (200ms) provides smooth page transition

Key behaviors

  • Sidebar skip: If already on that page, if (page.equals(activePage)) return; prevents re-navigation
  • Active state: Sidebar tracks activeButton and activePage to highlight the current nav item
  • Error handling: navigateTo() is wrapped in try-catch; errors show a card instead of crashing
  • TopBar updates: Title changes to match the current page
  • Safe transitions: Old FadeTransition is stopped before starting a new one (prevents content disappearing on rapid clicks)

9. Search System

The search bar is in the TopBar and works as follows:

  1. TopBar.setSearchCallback(Consumer<String>) registers a listener on the text field
  2. When text changes, Main.filterSearch(query) is called
  3. filterSearch() checks the current page type and calls filterTable(query) on it
  4. Each page implements filterTable(String query) which filters the TableView items
  5. Works on: FlightsPage, PassengersPage, PilotsPage, CoPilotsPage
  6. Search is case-insensitive, partial match (contains)

10. Chat System (LAN)

Server (Python)

  • File: server/server.py
  • TCP socket server on 0.0.0.0:5555
  • Threaded: each client gets its own thread
  • Broadcasts messages to ALL clients (including sender)
  • Appends \n to every message (required for Java's readLine())
  • Handles client disconnect gracefully
  • Uses SO_REUSEADDR for quick restart

Client (Java)

  • File: chatclient.java
  • Connects via Socket, sends nickname first
  • Reads messages in a background thread, updates TextArea via Platform.runLater()
  • Uses UTF-8 encoding (supports Arabic text)
  • Auto-flushes output with PrintWriter(out, true)

11. Reports System

5 report types, all generated as formatted text strings:

  1. Flight Report: Lists all flights with ID, destination, captain, seats, passengers count, co-pilots, status
  2. Passenger Report: Lists all passengers from all flights with full details
  3. Pilot Report: Lists all pilots with salary, hours, licenses
  4. Co-Pilot Report: Lists all co-pilots with salary, hours, languages
  5. Full Summary: Combined overview of everything

Reports display in a monospace TextArea. "Save as .txt" uses FileChooser + Files.writeString().

13. Bugs Fixed During Development

13.1 Content disappearing when navigating

FIXED Main.java:69-72 — Two-part fix: (1) Wrapped the navigateTo() switch in try-catch so exceptions show an error card instead of blank screen. (2) Stored the current FadeTransition in currentFade and stopped it before starting a new one. Previously, each navigation created a new FadeTransition without stopping the old one — multiple competing transitions fought over the opacity property, leaving it stuck at 0.0 (invisible). Also set centerStack.setOpacity(1.0) before clearing to ensure content is always visible.

14. Known Issues & Limitations

Data Persistence: All data is stored in static ArrayLists in adding.java. Data resets every time the application is restarted. No database or file-based storage is implemented.
  • No data persistence: ArrayLists reset on restart. Needs database or file storage.
  • Passengere class: Does not extend Person; has duplicate fields.
  • static ID counters: ID counters are static and don't reset, so IDs keep incrementing across instances.
  • Server broadcast to all: Sender sees their own message too (duplicated).
  • No user authentication: No login system; the app is single-user.
  • ChatWindowController.java: Excluded from compilation (legacy unused file).
  • Unchecked warnings: Compiler warnings about unchecked/unsafe operations (raw types).
